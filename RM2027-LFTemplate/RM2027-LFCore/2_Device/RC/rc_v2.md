## 原代码是：
```
const int index = constrain(
    (int(value) - offset) / span + 1,
    0,
    2
);
```
## ET08A 的参数是：
```
offset = 1024
span   = 670
```
## 在 C++ 中，两个整数相除时，结果向零取整，不是向下取整：
```
(-669) / 670 == 0
(-670) / 670 == -1
(-671) / 670 == -1
```
## 因此原算法实际得到：

|通道值	|差值|	除以 670|	最终档位|
|---|---|---|---|
|353|	-671|	-1	|上档 1|
|354|	-670|	-1	|上档 1|
|355|	-669|	0|	中档 3|
|1024|	0|	0|	中档 3|
|1693|	669|	0|	中档 3|
|1694|	670	|1	|下档 2|


## 所以原代码中，上档只有 353~354 两个值，下档基本只有 1694，有效范围非常窄。接收机采样值从 353 稍微跳到 355，就会被解析成“上档→中档”，随后再跳回 353，又变成“中档→上档”，造成模式反复变化和重复响。

现在的算法改成三等分：
- < 801        上档
- 801~1247     中档
- > 1247       下档
因此 353 和 355 都会稳定判为上档，不会因为微小采样抖动反复切换模式
